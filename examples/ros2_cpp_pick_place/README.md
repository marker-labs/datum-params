# ROS 2 C++ pick-and-place example

This ROS 2 Jazzy example mirrors the local pick-and-place demo's interfaces without using `rclpy`:

- `pick_place` is an `rclcpp` action client. It subscribes to `geometry_msgs/PoseStamped` on `/pick_target`, reads gripper feedback on `/joint_states`, and sends six successive `control_msgs/FollowJointTrajectory` goals to `/arm_controller/follow_joint_trajectory`.
- `motor_sim` is an `rclcpp_action` server that validates and interpolates the same six joints as the local kinematic motor simulator. It publishes `/joint_states`. It does not simulate a workpiece, grasp contact, collision or physics. Do not run it alongside another action server on the same action name.
- The controller compiles against a `parameters.hpp` generated by `datum-params`. Its effective tool length is `forearm_length_m + gripper_palm_length_m + finger_length_m / 2`; the shoulder and upper-arm dimensions also come from that header.

The example accepts target poses in `base_link` only. Unlike the local Python node, it does not perform TF transforms, accept dimensional parameter overrides, repeat, or execute against the Bullet backend out of the box. The generated C++ constants do not verify source hashes at runtime; regenerate and rebuild after changing CAD or its spec. This is a simulator demonstration, not hardware safety validation.

## Run with the included Docker image

Install Docker, Rust/Cargo, a C++17 compiler, and `solidcraft-cli` on the host. From a fresh `datum-params` checkout, generate native CAD and the changed header using the companion example. Choose **new** output directories. Use a directory Docker can mount; the examples below use the checkout:

```sh
examples/cpp-pick-place/run.sh "$PWD/.demo-cpp-inputs"
docker build -t dparams-ros2-cpp-demo -f examples/ros2_cpp_pick_place/Dockerfile .
docker run --rm -v "$PWD:/workspace:ro" dparams-ros2-cpp-demo \
  bash -c '/workspace/examples/ros2_cpp_pick_place/smoke.sh /workspace/.demo-cpp-inputs/changed/datum /tmp/ros-smoke'
```

The script builds the C++ ROS package and first starts the controller without a motor server. It verifies the missing-server timeout, starts the server, and republishes the target to verify recovery. The default action-server timeout is 10 seconds; set the `action_server_timeout_sec` ROS parameter to a positive value to change it. After a timeout, publish a new target to retry. The expected log progresses through APPROACH, DESCEND, GRASP, LIFT, TRANSFER and RELEASE, followed by `Pick and place sequence complete`. Logs are in the container's `/tmp/ros-smoke` during the run. The input directory contains the saved native CAD, spec, manifest, and generated header; remove that disposable directory after reviewing it.

To use an existing saved project, generate `parameters.hpp` from its reviewed spec first and pass that header directory to `smoke.sh`. It must contain `shoulder_height_m`, `upper_arm_length_m`, `forearm_length_m`, `gripper_palm_length_m`, and `finger_length_m` in the `datum::robot::main` namespace. The example compiles them into the node; it does not dynamically load the Python interface.

## Native ROS 2 workspace

With ROS 2 Jazzy, `colcon`, `control_msgs`, and the package's other dependencies installed, source `/opt/ros/jazzy/setup.bash` and run:

```sh
examples/ros2_cpp_pick_place/smoke.sh /absolute/path/to/generated/datum /tmp/dparams-ros2-cpp
```

The workspace argument must not exist. For interactive use, build the package with `-DDPARAMS_HEADER_DIR=/absolute/path/to/generated/datum`, source the install setup, and launch `ros2 run dparams_cpp_pick_place motor_sim` and `ros2 run dparams_cpp_pick_place pick_place` in separate terminals. Publish a `PoseStamped` to `/pick_target`; the automated script shows the exact message.

CI uses small synthetic SolidCraft-shaped ZIP fixtures solely to exercise header generation without installing the proprietary CAD application. The separately documented companion run uses real native SolidCraft files. Neither check proves CAD-to-URDF fidelity or contact physics.
